current behavior, Architecture owns implementation boundaries, and the export
contract owns evidence/arithmetic. Codex implements approved decisions and reports
unresolved material conflicts. Tests and receipts are evidence, not product authority.

## Single-schema replacement

The latest explicit clean-replacement instruction supersedes the prior multi-version
integration plan and its historical-test/compatibility preservation requirements.
Schema 5 is the sole format. Earlier prototypes were development iterations, not
supported customer releases. Their code, DDL, tests and provenance remain accessible
through Git history; no parallel execution paths are required.

Select one application, SQLite store, database worker, transaction owner, current
domain-service implementation, semantic verifier and Tk UI. Consolidate useful
algorithms into current modules and remove old wrappers, candidate bridges and
schema policies. Do not introduce a migration, upgrade, conversion, import, legacy
backup/restore route or historical qualification framework.

## Mandatory real-project ownership

Every task and frozen task row has a real project foreign key. Projects nest without
a fixed depth limit; tasks have three levels independently. New Task uses one owned
name/project dialog: prefill an explicitly selected real project, otherwise require
selection; a selected task creates its immediate child in its inherited project.
There is no default project or Unassigned container. Project organizational Root is
valid and remains distinct from a prohibited projectless task destination.

historical runtime adapters/tests and source-bound focus/qualification tooling are

separate current-source review and execution; no native acceptance, merge, release
or pilot follows. Stage 4 IN PROGRESS; Stage 5 NOT STARTED.
